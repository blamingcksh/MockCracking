─────────────────────────────────────────────────────────────────────────────────────────────────
QUESTION TYPES — pick exactly one
─────────────────────────────────────────────────────────────────────────────────────────────────
single_correct    Four options, exactly one correct. Also covers JEE Main
                  Section A. If the paper says "ONLY ONE of these options is
                  the correct answer", this is the type.
multi_correct     Four options, "ONE OR MORE THAN ONE" correct. Always emit
                  TWO OR MORE letters in `correctOptions` — a multi-correct
                  with a single correct option is a transcription error.
numerical         A NUMERICAL VALUE, no options. The printed answer may be an
                  exact value OR a range. Emit a number for an exact value and
                  {min,max} for a printed range like "[3.9 TO 4.1]". If a
                  printed unit is given, put it in `unitLabel`.
match_list        A Matching List Set: ONE MCQ built from List-I (4 entries
                  (P),(Q),(R),(S)) and List-II (5 entries (1)-(5)), with FOUR
                  combination options. Emit listI (4), listII (5), the four
                  combination options, and `matchAnswer` = the single correct
                  option letter. No partial credit exists for this type.
stem_subquestion  One numerical question belonging to a shared "Question Stem
                  for Question Nos. X and Y" passage. Exactly TWO questions
                  share each stem. Give both the SAME `groupId` (e.g.
                  "stem-phy-p2-1"). The stem text itself lives in the `stem`
                  of the FIRST of the pair; the second carries its own question
                  text. Scored +2 each, never negatively.

`altAnswers` is for papers whose official key genuinely accepts more than one
selection, e.g. "A or B" or "BD or D" → `altAnswers: [["A","B"], ["D"]]`.
Omit it (empty array) unless the source prints that.

PAPER REALITY — how real JEE papers are built
─────────────────────────────────────────────────────────────────────────────────────────────────
1. SECTION ASSIGNMENT. `paper` and `section` must reflect where the question
   actually sits in the printed paper. The app uses these two fields to place
   each question into the matching blueprint slot of that exam, and then asks
   you to sit exactly this paper — so a wrong section corrupts the paper's
   structure. 2026 blueprint (all three subjects identical):
     Paper 1 — S1 single_correct(4) · S2 multi_correct(4) · S3 numerical(4)
               · S4 match_list(4)
     Paper 2 — S1 single_correct(4) · S2 multi_correct(5) · S3 numerical(5)
               · S4 stem_subquestion(4 = 2 stems x 2)
   2025 blueprint:
     Paper 1 — S1 single_correct(4) · S2 multi_correct(3) · S3 numerical(6)
               · S4 match_list(3)
     Paper 2 — S1 single_correct(4) · S2 multi_correct(4) · S3 numerical(8)
   JEE Main 2026 — per subject: Section A single_correct(20), Section B
               numerical(5). `paper` is 1, section is 1 for A and 2 for B.
   If the source paper does not match any of these, still classify by the
   question's own type and set `paper`/`section` to the nearest blueprint slot.
   `marks` and `negative` must be the printed values for each question; every
   question in the same printed section carries the same pair, because the app
   builds one scored section per (subject, section, type, marks, negative)
   group and there is NO fixed question count or total-marks target anymore.
2. DIFFICULTY ESCALATION. Within a printed section, question numbers ascend in
   difficulty. Your `qElo` MUST ascend with the printed question number. Do not
   emit a later question with a lower qElo than an earlier one in the same
   section unless it is genuinely so (a numerical error-check item).
3. THE MULTI-CORRECT SECTION IS THE DISCRIMINATOR. In Advanced the hardest
   marks sit in S2. Its options are STATEMENTS about a shared setup ("P has two
   lone pairs", "Q can act as a fluorinating agent"), not four competing values.
   Write distractors that are plausible for a student who half-understood.
4. SINGLE-CORRECT IN ADVANCED IS NOT EASY. These carry −1 and sit at 1550-1900
   for most items. Reserve qElo < 1400 for genuine one-idea recalls.
5. NUMERICAL ITEMS HIDE TRAPS. Rounding to the printed precision, unit
   conversion, sign, and "enter the value of the dimensioned quantity" are the
   usual traps. When the paper prints a range, the range IS the key.
6. MATCH-LIST ENTRIES ARE OFTEN FIGURES. Physics List-I entries are frequently
   loop/circuit diagrams; Chemistry List-I entries are frequently reaction
   schemes. Crop every one of them — a match-list question is almost never
   text-only.
7. CHAPTER MIX. Advanced sections roughly follow the relative weight of units:
   Physics leans Mechanics and Electricity and Magnetism; Mathematics leans
   Algebra, Calculus and Coordinate Geometry; Chemistry is spread across
   Physical/Inorganic/Organic. Do not let one chapter dominate a section.

─────────────────────────────────────────────────────────────────────────────────────────────────
MANDATORY JSON & LATEX ESCAPING
─────────────────────────────────────────────────────────────────────────────────────────────────
Every LaTeX backslash inside a JSON string MUST be DOUBLE-ESCAPED. A single
backslash becomes a control character or a fatal parse error.

THE ESCAPE LADDER:
  Desired                | Parsed string | Raw JSON you emit
  LaTeX command          | \frac         | \\frac
  Matrix/align ROW BREAK | \\            | \\\\
  Visual line break      | <newline>     | \n

  • NEVER emit raw `\\n` — it renders a red "\n" mid-stem.
  • NEVER emit raw `\\` right before a digit or space.
  • A newline is a JSON escape, not LaTeX: emit `\n`.

HARD CRASHES — a single `\` MUST be followed by one of " \ / b f n r t u.
Anything else FATALLY CRASHES the parser:
  \alpha \angle -> \a   \cos \cap -> \c   \sum \sin -> \s   \lim \le -> \l
  \pi \pm \partial -> \p   \int \in -> \i   \mu \mathbb -> \m
  ALWAYS double: \\alpha, \\cos, \\sum, \\in, \\mathbb.

SILENT CORRUPTIONS — valid JSON escapes that still break the maths:
  \theta \tau \tan \times -> \t (TAB) -> "heta", "an"
  \neq \nabla \neg \not   -> \n (NEWLINE) -> "eq", "abla"
  \phi \forall            -> \f (FORM FEED) -> "hi", "orall"
  \right \Re              -> \r (CARRIAGE RETURN) -> "ight"
  \bar \because           -> \b (BACKSPACE) -> "ar"

TEXT-MODE, OUTSIDE $...$:
  • Currency dollars: "Cost is $5" MUST be `\\$5`.
  • Percent: "50%" MUST be `50\\%` — otherwise LaTeX eats the rest of the line.
  • Ampersand and underscore: `\\&` and `\\_`.
  • A stem mixing prose and maths is fine — just wrap every maths span in $...$
    or $$...$$.
  • Wrap an ENTIRE \begin{env}...\end{env} in ONE pair of delimiters. Never emit
    <LaTeX> tags — the app does not understand them.

CHEMISTRY & UNITS:
  • No raw unicode maths glyphs. Use \neq \le \ge \pm \times \infty \equiv
    \to \circ \mu, not ≠ ≤ ≥ ± × ∞ ≡ → ° µ.
NO LITERAL NEWLINES inside a JSON string value — press nothing; use \n.
